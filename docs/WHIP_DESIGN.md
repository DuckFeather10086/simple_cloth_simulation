# 鞭子模拟方案

状态：方案，尚未实现专用模式。复用 Simple Cloth 1.3 的代理节点、指定 Hook、碰撞和缓存操作。

## 操作目标

1. 在已有 Mesh 上选择鞭身部分，使用局部连续网格入口生成代理；或单独画 / 编辑新鞭身中心线。指定手柄、鞭根、鞭梢。
2. 把根部小段的两个以上节点固定到手柄或手骨，控制位置与朝向；鞭梢放开。需要抓住鞭身时，把中间节点指定到另一个 Hook。
3. 选择“软绳 / 皮鞭 / 较硬鞭身”的初始参数，再调粗细、回弹、阻尼、抗拉和模拟精度。
4. 连续播放预览，清缓存调整，最终烘焙。外观是连续、渐细的鞭身，不排列铁链环。

## 代理与运动

裸边链缺少可靠的截面与扭转约束。先沿用现有 Soft Body 方截面带，生成有横撑和相邻截面连接的细长代理；每段截面沿长度缩小，让根部较硬、末端较软。

质量向鞭梢递减，固定区域之外平滑过渡。优先控制拉伸：动作应通过弯曲传到末端，而不是靠伸长产生“甩”的感觉。提高抗拉后同步提高求解精度，检查每帧的总长和最大段长变化，不能只看末端是否动得大。

代理段数与求解步数要随速度和曲率增加；可从几十段开始试验，不能把某个固定值当作所有动画的保证。手柄动画也需要足够密的时间采样。低速摆动、地面拖行、快速甩动分开调试。

## 外观与碰撞

沿代理生成渐细的连续鞭身；保持基础路径可编辑，外观细分在模拟之后。碰撞厚度需要与实际鞭身半径对应，重点检查鞭梢与地面、身体的穿越。

已有身体 / 地面 Collision 可以复用。绕住物体后收紧涉及接触、摩擦与长度约束，应作为独立验证场景。现有链条只碰撞代理顶点，不能直接据此宣称高速细鞭不会穿插。

## 验证与后续分界

- 固定手柄、释放鞭身：静置下垂且不持续抖动。
- 动画手柄：动作逐段向末端传播；改变帧率后行为应相近。
- 总长与最大段长：检查甩动中的拉伸，避免橡皮筋效果。
- 平面 / 圆柱碰撞：检查拖地、扫过障碍与绕行。
- 清缓存、烘焙、保存重开：与现有统一面板一致。

第一版目标是可调的甩动、拖地和一般碰撞。若原生 Soft Body 在高速情况下仍无法同时满足拉伸与稳定性，再评估专门的杆 / 绳约束求解器；仍保留同一套面板与 Hook 工作流。鞭梢超音速与声学不在当前实现范围内。
